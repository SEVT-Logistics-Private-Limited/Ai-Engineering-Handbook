# 14 — Project Portfolio

This directory connects the concepts in the handbook to practical engineering work.

## Project documentation standard

For each project, record:
1. Problem statement and intended users
2. Requirements and non-goals
3. System architecture and component diagram
4. End-to-end data flow
5. Technology choices and alternatives
6. Implementation details with exact source links
7. Tests, validation and measurable results
8. Challenges, debugging and resolutions
9. Security, privacy, latency and cost considerations
10. Lessons learned and future improvements
11. Interview-ready project explanation

## Project evidence policy

Use one of these labels:
- **Implemented and verified:** exact source/test evidence is linked.
- **Partially implemented:** specify what works and what remains.
- **Studied / prototyped:** explored but not integrated into a complete project.
- **Planned:** not implemented yet.

Do not publish confidential code, credentials, private customer data or internal company information. Use sanitized examples where needed.
